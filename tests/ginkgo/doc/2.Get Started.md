## 1. What is Ginkgo?

Ginkgo is a modern, high-performance C++ numerical linear algebra library designed for sparse linear systems, optimized for:

- NVIDIA GPUs (CUDA)
- AMD GPUs (HIP)
- Intel GPUs (oneAPI/DPC++)
- Multicore CPUs (OpenMP)

Its focus is:

- Low-level performance (GPU-accelerated kernels)
- High-level usability (simple interfaces)
- Portability (same code runs on CPU, CUDA, HIP, DPC++)

## 2. The Key Concepts

### Executors

-> Executors control where computations run (CPU, GPU, multicore, etc.) and manage memory, kernels, and backend dispatch.

- OmpExecutor → CPU
- CudaExecutor → NVIDIA
- HipExecutor → AMD
- DpcppExecutor → Intel/oneAPI


### Sparse Matrix Formats

Ginkgo supports many formats and converts between them:

- CSR (Compressed Sparse Row)
- COO (Coordinate)
- ELL, SELL-P, Hybrid
- Dense
- Block-Jacobi structure

### Solvers

-> These are the main solvers used for large sparse systems.

| **Solver Name**                          | **Ginkgo Class**         | **Type / Description**                       | **Matrix Type**                |
| ---------------------------------------- | ------------------------ | -------------------------------------------- | ------------------------------ |
| **Conjugate Gradient (CG)**              | `gko::solver::Cg`        | Krylov solver for SPD systems                | Symmetric Positive Definite    |
| **BiConjugate Gradient (BiCG)**          | `gko::solver::Bicg`      | Krylov solver for nonsymmetric systems       | General nonsymmetric           |
| **BiCGStab**                             | `gko::solver::Bicgstab`  | Stabilized BiCG                              | General nonsymmetric           |
| **Conjugate Gradient Squared (CGS)**     | `gko::solver::Cgs`       | Iterative solver for nonsymmetric systems    | General nonsymmetric           |
| **Compressed-Basis GMRES (CbGmres)**     | `gko::solver::CbGmres`   | GMRES variant with compressed basis          | General nonsymmetric           |
| **Generalized Minimal Residual (GMRES)** | `gko::solver::Gmres`     | Classic GMRES                                | General nonsymmetric           |
| **Flexible Conjugate Gradient (FCG)**    | `gko::solver::Fcg`       | CG variant allowing variable preconditioning | SPD variants                   |
| **Generalized Conjugate Residual (GCR)** | `gko::solver::Gcr`       | Krylov residual method                       | General nonsymmetric           |
| **Induced Dimension Reduction (IDR(s))** | `gko::solver::Idr`       | Efficient Krylov for nonsymmetric            | General nonsymmetric           |
| **MINRES**                               | `gko::solver::Minres`    | Krylov for symmetric indefinite              | Symmetric / Hermitian          |
| **Iterative Refinement (IR)**            | `gko::solver::Ir`        | Improves solution via iterative correction   | Any (wrapped with base solver) |
| **Lower Triangular Solve**               | `gko::solver::LowerTrs`  | Solve L x = b                                | Triangular operators           |

| **Multigrid**                            | `gko::solver::Multigrid` | Multilevel solver                            | General (PDE systems)          |


### Logging

Ginkgo can Log:

- iteration count
- residual norm
- stopping criteria

```c++
// Create a Convergence Logger
auto logger = gko::log::Convergence<>::create();
solver->add_logger(logger);
// Run the solver
solver->apply(b, x);
std::cout << "Iterations: " << logger->get_num_iterations() << "\n";
std::cout << "Final residual: " << logger->get_residual_norm() << "\n";
```

### Preconditioners (Accelerate convergence)

https://ginkgo-project.github.io/ginkgo-generated-documentation/doc/develop/group__precond.html

| **Preconditioner**                               | **What It Does (Concept)**                                                                      | **Best Used For**                                                                                            | **Ginkgo Class**                                          |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------- |
| **Jacobi / Block-Jacobi**                        | Approximates (A^{-1}) with a **block-diagonal inverse**. Each block is inverted independently.  | Fast, parallel-friendly baseline preconditioner; good smoother for multigrid; works for most sparse systems. | `gko::preconditioner::Jacobi`                             |
| **ILU (Incomplete LU)**                          | Builds an **approximate LU factorization** with limited fill-in: (A \approx LU).                | Nonsymmetric or general sparse systems; strong general-purpose preconditioner.                               | `gko::preconditioner::Ilu`                                |
| **IC (Incomplete Cholesky)**                     | Approximate **Cholesky** factorization for SPD matrices: (A \approx LL^T).                      | Symmetric positive definite systems (e.g., CG on PDEs).                                                      | `gko::preconditioner::Ic`                                 |
| **ISAI (Incomplete Sparse Approximate Inverse)** | Computes a **sparse approximate inverse** directly, often for the triangular factors of ILU/IC. | Highly parallel architectures (GPUs); when explicit approximate inverses accelerate solves.                  | `gko::preconditioner::Isai`                               |
| **Gauss–Seidel**                                 | Triangular splitting: forward/backward substitution using (D - L) or (D - U).                   | Sequential or mildly parallel scenarios; smoothers; simple structured problems.                              | `gko::preconditioner::GaussSeidel`                        |
| **SOR / SSOR**                                   | Gauss–Seidel with **over-relaxation** parameter ( \omega ) to speed convergence.                | Similar to Gauss–Seidel but tunable; legacy algorithms; structured matrices.                                 | `gko::preconditioner::Sor`                                |
| **Distributed Schwarz (Experimental)**           | Overlapping or nonoverlapping **domain decomposition**; solves subdomain problems in parallel.  | Distributed parallel solves using multiple nodes; large-scale PDE systems.                                   | `gko::experimental::distributed::preconditioner::Schwarz` |


```c++
auto solver = gko::solver::Cg<>::build()
    .with_criteria(
        gko::stop::Iteration::build().with_max_iters(100).on(exec),
        gko::stop::ResidualNorm<>::build()
            .with_reduction_factor(1e-6)
            .on(exec))
    .with_preconditioner(
        gko::preconditioner::BlockJacobi<>::build().on(exec)
    )
    .on(exec);
```

## Ginkgo Workflow

### 1 — Choose an executor

```c++
auto exec = gko::CudaExecutor::create(0, gko::OmpExecutor::create());
```

### 2 - Load or build the matrix and vectors

```c++
auto A = gko::read<gko::matrix::Csr<double>>(file, exec);
auto b = gko::read<gko::matrix::Dense<double>>(file2, exec);
auto x = gko::matrix::Dense<double>::create(exec, b->get_size());
```

### 3 - Choose stopping criteria

```c++
auto stop = gko::stop::Combined::build()
    .with_criteria(
        gko::stop::Iteration::build().with_max_iters(1000).on(exec), // Iterations
        gko::stop::ResidualNormReduction<>::build() // ResidualNorm
            .with_reduction_factor(1e-8).on(exec))
    .on(exec);
```

### 4 - Choose a preconditioner (Optional but important)
```c++
auto ilu = gko::preconditioner::Ilu<double>::build().on(exec);
```

### 5 - Build a solver (factory pattern)

```c++
auto solver =
    gko::solver::Gmres<double>::build()
        .with_preconditioner(ilu)
        .with_criteria(stop)
        .on(exec);
```

### 6 - Generate solver with respect to matrix A
```c++
auto gmres = solver->generate(gko::share(A));
```

### 7 - Solve the system
```c++
gmres->apply(gko::share(b), gko::share(x));
```

### 8 - Verify solution (optional)
```c++
auto r = gko::matrix::Dense<double>::create(exec, b->get_size());
A->apply(x, r);
r->add_scaled(-1.0, b);
```
Residual norm:
```c++
auto norm = gko::matrix::Dense<double>::create(exec, gko::dim<2>{1,1});
r->compute_norm2(norm);
std::cout << "Residual = " << norm->at(0,0) << std::endl;
```

## Notes
- Ginkgo does not provide GPU-aware MPI internally, but it can work with GPU-aware MPI if you use it in your application.
- Random matrices often break ILU/ParILU. If ParILU produces NaNs:
    - Your matrix is not diagonally dominant
    - Or contains zero pivots
    - Or is singular
    - Or structure is incompatible with LU
- Why gko::share?
  Because Ginkgo expects a std::shared_ptr<LinOp> for chaining operators.
